# Domain Docs

This repository uses a single domain context.

Before exploring an area, read the root `GLOSSARY.md` and relevant decisions
in `docs/adr/`, if they exist. If either is absent, proceed silently; domain
documentation can be created when terminology or decisions are resolved.

Use the glossary's terms in issues, proposals, hypotheses, and test names.
If a needed concept is absent, reconsider the terminology or note the gap
for domain modeling.

If a proposal contradicts an existing ADR, explicitly identify the conflict
rather than silently overriding the decision.
