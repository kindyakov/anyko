# Постоянная сессия работы и отдельные потоки попыток

Пользователь возвращается к работе и дополняет её документами, сохраняя решения и контекст. Модуль `agents` владеет одной логической сессией работы и последовательностью принятых обращений. `facts` остаётся владельцем кандидатов, источников и ручных решений. `workflows/works` продолжает сессию после анализа исходников; будущий чат использует эту же границу продолжения, но транспорт и пользовательские сообщения сейчас не реализованы.

Общий изменяемый поток Mastra для всех обращений отвергнут: SDK сохраняет сообщения до принятия прикладного результата, поэтому ответ просроченной попытки мог бы повлиять на следующий запуск. Каждое обращение получает отдельный зарегистрированный поток Mastra. Постоянный контекст восстанавливается из последнего принятого состояния и актуальных фактов; устаревшая история попыток не воспроизводится автоматически. Это одна логическая сессия с цепочкой принятых состояний, а не один бесконечный provider thread.

Сопоставление использует готовые Mastra Agent, Memory, Tools и PostgreSQL store. Модель получает ограниченную сводку и список источников, а актуальные поля и фрагменты читает разрешёнными инструментами. Сводка не является evidence. Предложения координатора добавляются к исходным кандидатам с отдельным происхождением; подтверждённые и ручные поля защищает `facts`. Точная цитата проверяет доступность источника, но не доказывает истинность интерпретации.

Принятые факты, новое состояние сессии, запись обращения и итог запуска фиксируются одной транзакцией. CAS по token запуска удерживает row lock до commit; проверяются также редакции входов, работы и сессии. Изменение ручных полей допускает одно повторное сопоставление с актуальными сведениями. Повторное устаревание или сбой модели сохраняют известные кандидаты и дают частичный результат без принятия старой сводки.

Удаление любого исходника скрывает контекст немедленно, а после дренирования WorkIo удаляет всю смешанную историю, сессию и зарегистрированные потоки Mastra. Следующее продолжение оставшихся документов создаёт новую сессию. История не является обходным способом сохранить удалённые сведения.
