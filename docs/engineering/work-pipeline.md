# Работы, модели и заполнение документа

Требования: [Issue #2](https://github.com/kindyakov/anyko/issues/2) и последующее поручение о пакете из трёх документов; [ADR 0006](../adr/0006-document-packages.md) уточняет [ADR 0005](../adr/0005-template-works-and-agent-runtime.md). Пользователь выбирает пакет из 1..N шаблонов. Текущий пакет `bfl-bankruptcy-v3` содержит `bfl-statement-v3`, `bfl-inventory-v1`, `bfl-creditors-v1`. Исходные заполненные DOCX обезличены; их оригиналы не являются runtime-зависимостью и не предназначены для публикации.

## Владельцы и исполнение

`works` владеет работой, связями с исходниками, редакцией и событиями. `documents` сохраняет исходники, результат MinerU и отдельные изображения в закрытом S3. `processing` владеет запусками, шагами, outbox, lease и версиями подключения. `facts` сопоставляет кандидаты и сохраняет ручные решения. `templates` предоставляет неизменяемый бланк; `generation` хранит снимок значений и собранные DOCX. `agents` использует Mastra и PostgreSQL-память в схеме `anyko_agents`.

Координация — `workflows/works`, сборка и ресурсы — `runtime/works`. Серверный `@anyko/llm` не знает Prisma, пользователей, файлов и очереди: создаёт SDK-модель по явно переданным настройкам. Пакет запрещён для web/contracts/ui. Next-маршруты компонуют feature `works` через общий экран сессии.

Три процесса остаются прежними. Worker обслуживает очереди OCR и `anyko-work-pipeline`. Запуск и outbox фиксируются атомарно в PostgreSQL; Redis не хранит единственную копию намерения. Envelope содержит версию, scope и run ID. CAS по attempt token и lease защищает принятие результата; просроченный запуск и его outbox восстанавливаются одним SQL-оператором.

Этапы: парсинг/OCR → описания изображений → извлечение по файлам → сопоставление → отдельная генерация DOCX. Ошибка файла сохраняется, остальные обрабатываются. Успешные шаги извлечения повторно используются при неизменных входах и версии подключения. Сбой до сохранения успешного ответа может потребовать повторного платного вызова: exactly-once для провайдера не обещается.

## Агентский контекст и данные

Текст целиком подаётся фрагментами до 64000 символов с перекрытием 2000. У агента максимум три шага, ответ до 12000 токенов, один SDK retry и deadline 120 секунд на вызов. У запуска deadline 25 минут, lease 30 минут; параллелизм потребителя — один. История Mastra ограничена 12000 токенов, semantic/observational memory и автоматические заголовки выключены. Большой контекст разбивается; отсутствие данных остаётся неизвестным. Zod и точная цитата не доказывают истинность извлечения — сведения проверяет человек.

Фотографии и изображения DOCX дополнительно нормализуются процессором в JPEG; все кадры TIFF учитываются с лимитом 32. Оригинал сохраняется отдельно. Байты изображения передаются модели только в запросе, не дублируются в сообщениях Mastra. Описания и кандидаты — версионированный JSON шага с путями исходных изображений. Неподдержанная графика DOCX и превышение лимитов дают явную ошибку.

Ручные правки имеют приоритет; противоречащие значения остаются кандидатами, поле не выбирается произвольно. Сохранение требует актуальную редакцию. Генерация фиксирует значения, подтверждение и версию пакета; поздняя правка не меняет старый результат. Шаблон сохраняется в S3 под версией и checksum и проверяется перед сборкой через docxtemplater/PizZip. Строки обязательств сопоставляются по кредитору/должнику и основанию; конфликтующие значения сохраняются для проверки. Неизвестный состав (`null`) отличается от явно указанного отсутствия (`[]`). Просительная часть и приложения не наследуются из конкретного дела.

## HTTP, SSE и настройки

`/api/document-packages`, `/api/works`, `/api/works/:id` дают каталог, список и снимок. Подмаршруты работы: `documents`, `analyze`, `fields`, `confirm`, `generate`, `generations/:id/files/:fileId`, `events`. Источники и предпросмотр доступны через проверяемые `/api/documents/:id/source`, `/result`, `/images/:index`.

Scope получается из сессии и Membership; изменения проверяют origin. Чужой ID не даёт доступ к работе, событиям или скачиванию. `/api/settings/llm` меняет только owner. API не возвращает ключ; новый шифруется AES-256-GCM с workspace AAD. Запуск фиксирует revision подключения, смена модели применяется к новым запускам. Vision/extraction выбираются независимо, автоматического fallback между моделями нет.

Снимок читает cursor перед данными: изменения могут прийти повторно, но не пропасть между снимком и подпиской. SSE содержит только тип изменения и ID; UI перечитывает данные, сохраняя несохранённые правки. `Last-Event-ID` проходит через Next proxy. Соединение ограничено 25 секундами и переподключается; доступ проверяется каждую итерацию, лимит — четыре потока на пользователя и 100 на API-процесс. Прокси должен пропускать поток без буферизации.

Пакет и состав шаблонов записаны в `DocumentPackageVersion`, `DocumentTemplateVersion`, `PackageDocument`. Работа закрепляет `packageVersion`. `WorkGeneration` фиксирует общий снимок, `WorkGenerationFile` хранит отдельные статусы, ключи и checksums. Состав связан внешними ключами, успешный файл не скрывается из-за ошибки другого. Ошибка storage с неизвестным исходом продолжает подниматься до durable I/O барьера. Исторические версии сохранены; техническая версия скрыта из каталога UI, но её создание через API оставлено для совместимости старых клиентов.

[Подготовка DOCX и предпросмотра](../../packages/backend/src/modules/templates/assets/README.md): исходные стили и структура сохраняются, служебные поля заменяют данные конкретного дела. В браузере три бланка переключаются вкладками и используют общие значения. Полное совпадение браузерной пагинации и Word не обещается.

## Полное удаление и восстановление

Удаление исходника сразу скрывает зависимые сведения и скачивания. Cleanup ждёт durable DocumentIo/WorkIo барьеры, удаляет смешанные результаты работы, генерации и их S3-объекты, сообщения/сессии Mastra, затем снимает связь с исходником. После этого document cleanup завершает физическое удаление. Оставшиеся исходники можно обработать заново; ручные значения тоже очищаются, поскольку могли содержать удалённые сведения. UI предупреждает об этом до удаления.

Неопределённый исход S3 PUT оставляет `uncertain` барьер. После crash его нельзя снимать по возрасту. Оператор подтверждает остановку всех API/worker, завершение внешних записей и дренирование MinerU, затем запускает `bun run documents:recover-writes --applications-stopped --storage-requests-drained`. Команда восстанавливает также WorkIo; последующий worker очищает зарегистрированные ключи. Это не гарантия удаления у RouterAI/конечного провайдера или из резервных копий.

## Локальный запуск и доказательства

После `bun install --frozen-lockfile` и `bun run db:generate` примените миграции к локальной базе. В игнорируемом `.env`: `WORKS_ENABLED=true`, `DOCUMENTS_ENABLED=true`, приватный `LLM_CONFIG_ENCRYPTION_KEY` из 32 случайных байтов в hex. Ключ одинаков у API и worker; его потеря делает существующие подключения нечитаемыми.

Подключение задаётся owner через интерфейс. Для начального RouterAI есть `bun --env-file=.env --env-file=.env.routerai.local run llm:provision`: отдельный игнорируемый файл содержит `ROUTERAI_API_KEY` и `ROUTERAI_BASE_URL`. Команда сохраняет существующие настройки. Модель по умолчанию `~deepseek/deepseek-v4-flash-latest`, альтернативный ID `minimax/minimax-m3.1-flash` задаётся в настройках.

`bun run dev` загружает конфигурацию и запускает приложения. Не используйте hostname другого проекта: `APP_ORIGIN`, `AUTH_BASE_URL` и фактический адрес страницы должны совпадать. Секретов нет во frontend env.

`bun run test:llm` проверяет готовый SDK на контролируемом HTTP-провайдере. `bun run test:works` — приоритет правок и конфликты. `bun run test:works:integration` требует отдельную `anyko_test` и тестовый Redis: настоящие БД/outbox/BullMQ и управляемый agent port. `bun run test:processor` проверяет stateless lifecycle и визуальный экспорт. CI не выполняет платные LLM-запросы. Browser и live extraction — отдельные уровни доказательств.

## Повторы визуального анализа

Невалидный структурированный ответ Mastra/SDK и ошибка Zod-валидации описания допускают до трёх попыток получения валидного ответа, с паузами 1 и 2 секунды. Все попытки и задержки используют единый deadline описания (120 секунд по умолчанию) и сигнал отмены. Ошибки доступа, постоянные HTTP-ошибки и ошибки кода этим механизмом не повторяются. Внутри каждой попытки сохранён один транспортный retry SDK для временных ошибок: верхняя граница — шесть HTTP-запросов, если чередуются транспортные и структурные ошибки. Провайдер и модель при повторе не меняются.

Бюджет ответа описания — до 4800 токенов. Если потребовался повтор структурированного ответа, суммарный расход возвращается как неизвестный (`null`): SDK не отдаёт надёжный расход отклонённых ответов. Расход одной последней успешной попытки нельзя выдавать за точную общую стоимость. После исчерпания попыток файл получает ошибку, остальные исходники продолжают обрабатываться.

## Постоянный контекст работы

`agents` владеет `WorkAgentSession` и `WorkAgentTurn`; [ADR 0007](../adr/0007-persistent-work-agent-session.md) описывает выбор отдельных Mastra threads для попыток. Логическая сессия создаётся вместе с новой работой; существующие работы получают её при анализе. Сессия и её версия сохраняются в PostgreSQL, каждый принятый turn содержит revision, run ID, зарегистрированный thread ID, событие `documents.analyzed` и версионированный контекст/выход. Неудачные и устаревшие ответы остаются только историей попыток и не становятся принятым контекстом.

После извлечения из файлов `continue-session` восстанавливает факты и последнее принятое состояние. Координатор через `@mastra/core`/Memory получает перечень источников и состояния полей. Инструменты читают актуальные поля и текст/описания разрешённых исходников фрагментами до 16000 символов, с проверкой текущей работы на каждом чтении. Лимиты: 24 инструментальных чтения, 8 шагов, 12000 output tokens, общий timeout 120 секунд. Нет инструментов записи фактов и нет отдельного самописного agent loop.

Исходные кандидаты не подавляются моделью. Контекстные предложения имеют `origin=context`, проходят схемы и проверку точных цитат и отображаются отдельно. Сводка до 4000 символов не является доказательством. Пустые и противоречивые поля вычисляются из принятых фактов. Перед commit выполняется CAS-fence текущей попытки и проверка work/session revision. При ручной правке сопоставление пересобирается максимум один раз. При ошибке модельного этапа прежние кандидаты сохраняются; запуск становится partial, старая сводка остаётся явно устаревшей.

Кэш извлечения файлов сохраняется. Координатор запускается заново на каждом намеренном анализе, читает текущие факты и настройки; контекстный результат не кэшируется по одному document checksum. Смена провайдера не требует переноса его внутреннего reasoning state. Полная история принятых обращений сохраняется в БД, а в prompt отправляется ограниченное последнее состояние и актуальный канонический контекст. Будущий чат добавит источник сообщений и transport к этому владельцу; сейчас чата нет.

API снимка работы возвращает `session` с ID, revision, context и updatedAt. На странице показаны сводка, поля для проверки и предупреждение об устаревании после правки. Чтение снимка защищено work lock, чтобы session и facts соответствовали одной редакции. Удаление исходника очищает session/turns и все Mastra threads после существующего durable I/O барьера.
