# Примеры v1

Оцените пригодность описанного доказательства в указанном scope: `accept`, `reject` или `needs-context`. Укажите защищаемое требование, существенный недостаток при наличии и следующий способ проверки. Примеры схематичны, выполняемые fixtures здесь не подразумеваются.

## C1

Задача: заменить внутренний компонент `OldFactsPanel` новым, сохранив сценарий проверки фактов. Автор удалил старый файл и добавил единственный тест: `expect(existsSync('OldFactsPanel.tsx')).toBe(false)`. На основании этого объявил сценарий сохранённым.

## C2

Задача: удалить публичный endpoint `/api/legacy-export`; утверждённый контракт требует 404. Тест поднимает настоящий API, делает запрос по старому пути и проверяет 404. Другой тест проверяет доступность нового endpoint. Reviewer отклоняет первый тест только потому, что это «тест удаления».

## C3

Задача: запретить извлечению заменять подтверждённое юристом значение. Тест mock-ает саму функцию `mergeFacts`, задаёт ей возврат прежнего значения и проверяет возвращённый объект. Автор утверждает, что бизнес-правило проверено.

## C4

Задача: добавить правило анализатора, запрещающее импорт БД из web. Тест создаёт временные исходники, запускает настоящий анализатор и проверяет конкретное нарушение; допустимый локальный импорт отдельно проходит. Reviewer считает тест плохим из-за работы с текстом исходников.

## C5

Задача: исправить доступ к делу другой рабочей области. Новый тест делает реальный запрос пользователя A к делу B и проверяет отказ. В качестве доказательства силы теста автор удалил импорт сервера: запуск упал на компиляции. Отчёт: «негативный сценарий проходит, red-проверка защиты тоже пройдена».

## C6

Задача: внутреннее переименование локального helper без изменения контракта. Имеющиеся тесты поведения до и после проходят, reviewer сверил отсутствие изменения поведения. Новый тест не добавлен. Автор не заявляет проверки других runtime или deployment.

## C7

Задача: улучшить повторную обработку. Во время правки автор изменил expected с подтверждённого значения юриста на значение из последнего extraction. В задаче не определено, допустимо ли заменять ручное подтверждение; источник прежнего expected reviewer ещё не изучил. Автор объясняет изменение тем, что «так теперь работает алгоритм».
