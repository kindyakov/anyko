# Ключ v1

Читать после самостоятельной оценки [примеров](cases.md).

| ID | Ожидаемая оценка | Основание |
| --- | --- | --- |
| C1 | reject | Отсутствие внутреннего файла не доказывает сохранность сценария. Нужна проверка пользовательского поведения и оставшихся связей; отдельный тест удаления файла не нужен. |
| C2 | accept | 404 является явным публичным контрактом, проверяется настоящий API. Отклонение только за «удаление» — ложное срабатывание. Это не доказывает остальные свойства нового endpoint. |
| C3 | reject | Mock подменяет предмет проверки. Нужно исполнять настоящий merge/use case с заданными независимо исходными значениями. |
| C4 | accept | Исходники — вход анализатора, его диагностика — наблюдаемый результат. Положительный пример защищает от запрета всего подряд. |
| C5 | reject | HTTP-тест полезен, но заявленная red-проверка не доказана. Нужна контролируемая ошибка в проверке доступа с падением соответствующего assertion; compile error не подходит. |
| C6 | accept | Новый тест не обязателен для сохранения внутреннего поведения; существующие тесты и review соответствуют заявленному scope. |
| C7 | needs-context | Нельзя выводить требование из нового алгоритма. Найти источник прежнего expected и принятое правило; если продуктовая семантика остаётся неясной, уточнить конкретное поведение. Изменение не принимается лишь потому, что тест зелёный. |

Вариант C7 `reject` с явным отклонением неподтверждённой смены критерия и требованием выяснить источник тоже содержательно верен. Оценка учитывает объяснение, а не точное совпадение слова. Для C5 важно не отвергать полезный HTTP-тест целиком, а обнаружить недоказанное утверждение.
