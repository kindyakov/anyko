# Локальный stateless MinerU

Закреплены MinerU **4.1.7** и Python **3.12.15**. Установка:

```powershell
powershell -NoProfile -File infra/mineru/setup.ps1
powershell -NoProfile -File infra/mineru/start.ps1
```

Сервис слушает `127.0.0.1:8020`. `start.ps1` запускает Anyko-owned HTTP-адаптер
`infra/mineru/processor.py` поверх поддержанного `mineru.parser.parse_async`.
Tasks API, FileStore, document library и их retention-кэш не используются.
В `work/mineru/home` остаются только настройки и веса моделей; телеметрия выключена.

PDF и JPEG/PNG/WebP/TIFF/AVIF/HEIF используют Basic с автоматическим OCR.
Основной распознаватель — PaddleOCR `cyrillic_PP-OCRv5_rec_mobile`. Тот же
вес используется для текста таблиц, печатей и автонастройки устройства ONNX.
Детекторы текста и печатей определяют области для распознавания.
Имя штатного файла детектора текста начинается с `ch_`.

У MinerU 4.1.7 нет настройки языка Basic в `parse_async`. При запуске
процессор проверяет версию и сигнатуры нужных частей SDK, затем указывает
путь к распознавателю в общем реестре моделей и подключает его словарь.
Несовместимый SDK, backend без ONNX, отсутствующие или повреждённые файлы
останавливают запуск. Имя активной модели и SHA-256 веса пишутся в журнал
запуска и выводятся в `ocrRecognizer` в `GET /v1/health`.

В распознанных с растра токенах кириллические двойники заменяются
латинскими, если в токене есть однозначная латинская буква и все его
кириллические буквы имеют латинские двойники. Например, `QA-VТ-51`
становится `QA-VT-51`, а `ABСервис`, `B2BСервис`, `ПАО`, `ООО` и `AO`
сохраняются. Нативный текст PDF и Word проходит без этой нормализации.
Намеренно смешанная серия `QA-СТ-51` может стать `QA-CT-51`: пиксели
похожих букв не позволяют установить исходную письменность.

Для PDF процессор также проверяет покрытие текста. На скане при наличии
читаемого текста и покрытии обнаруженных строк геометрией блоков MinerU
проверка использует только детектор. Если геометрия указывает на пропуск,
в тексте осталась неоднозначная числовая запись или страница имеет нативный
слой, процессор проверяет содержание локальным распознавателем. Если
в разметке MinerU отсутствует
существенная часть уверенно прочитанных строк, для этой страницы публикуются
строки русского OCR в порядке чтения. Строки с низкой уверенностью и числа,
которые расходятся с пригодным текстовым слоем под тем же прямоугольником,
пропускаются. `pdf-ocr.json` сохраняет номер страницы, нормализованные
координаты и текст. У строк повторного OCR есть оценка уверенности. Когда
скан распознан с первого раза и строки однозначно сопоставлены с блоками
MinerU, в метаданные попадают текст и координаты этих блоков с признаком
`source: primary-ocr`. Для таких строк MinerU не возвращает оценку
уверенности. Если размер метаданных достигает лимита ZIP-потребителя,
сохраняются прежде всего координаты восстановленного текста.
Backend сохраняет эти данные вместе с результатом. Однозначная цитата ведёт
на страницу источника при проверке сведений в работе.
Markdown экспортируется по физическим страницам. Таблицы с соседних страниц
сохраняют отдельные границы, даже если MinerU принял их за продолжение.
При восстановлении текста страницы таблицы, иллюстрации, отдельные формулы и
абзацы с формулами сохраняются в разметке MinerU. OCR-строки внутри этих блоков
исключаются из восстановленного текста, чтобы не дублировать ячейки или части
формулы. Если первичный OCR сохранил только цифры, восстановленный текст
заменяет их блок при совпадении числовой записи. На страницах без текстового
слоя уверенно прочитанная строка кириллицы может заменить совпадающий по
координатам фрагмент из отдельных символов или цифр с пропущенными ведущими
нулями. Значащие цифры и разделители должны совпасть. Если первый проход
русского OCR перепутал нули с похожими буквами в числовой записи, процессор
проверяет её повторно на растре повышенной резкости и принимает только строку,
которую модель сама прочитала в том же месте с тем же окружающим текстом.
Офлайн-комплект Windows включает веса FormulaNet.

Тот же локальный OCR читает нормализованные пиксели изображений.
AVIF и HEIF/HEIC декодируются перед передачей в MinerU. Обрабатывается
основной кадр, а исходный файл хранится в оригинальном формате. Для HEIF
встроенный просмотр использует JPEG из результата распознавания.
При существенных пропусках уверенно распознанной кириллицы он заменяет
Markdown на строки русского OCR, упорядоченные сверху вниз и слева направо
в пределах строки. Этот путь доступен при прямом запросе к процессору.
В приложении для отдельно загруженного изображения воркер запрашивает
`/visual-inputs`: процессор подготавливает кадры, затем Vision транскрибирует
их с настройками подключения рабочей области. Переразбор уже сохранённых
результатов не запускается автоматически.

Локальный `setup.ps1` и сборка portable-компонента запускают
`prepare-pdf-ocr-model.py`. Скрипт скачивает вес из
[реестра RapidOCR](https://github.com/RapidAI/RapidOCR/blob/main/python/rapidocr/default_models.yaml)
и проверяет закреплённый SHA-256. Словарь берётся из метаданных того же
ONNX-файла, сохраняется в UTF-8 рядом с весом и сверяется по отдельному SHA-256.
`prepare-portable-models.py` скачивает закреплённые веса разметки, детекторов,
формул и таблиц. Китайский распознаватель не входит в подготовленный набор.
Для обновления существующего venv установите новые веса и перезапустите сервис.

```powershell
work/mineru/.venv/Scripts/python.exe -B infra/mineru/prepare-pdf-ocr-model.py work/mineru/home
```

При раздельном обновлении сначала обновите backend и worker, затем
процессор. Новые читатели понимают сохранённые результаты `+eslav.1` и
`+cyrillic-pdf.1`. Старый читатель ожидает оценку уверенности у каждой
строки и отклоняет строки первичного OCR нового процессора.

У PDF с несовместимым форматом результата MinerU интерфейс показывает
«Документ нужно распознать заново». Повтор создаёт новую ревизию без повторной
загрузки оригинала. При запуске анализа такой исходник ставится на повтор
автоматически.

Актуальный процессор сообщает `pdfOcrVersion: 1` и `imageOcrVersion: 1` в
`GET /v1/health`. Заголовок версии содержит суффикс `+cyrillic-pdf.1`
для PDF и `+cyrillic-image.1` для изображений.
Ответ старого процесса без `pdf-ocr.json` воркер считает несовместимым
для PDF и записывает `document_ocr_failed` с кодом `OCR_PROCESSOR_OUTDATED`.
Локальный журнал воркера находится в `apps/worker/.logs/runtime.log`.

При автоматическом переносе сведений ИНН и СНИЛС сверяются с цитатой и
проверяются по контрольным цифрам. Дата и общая сумма должны встречаться в
цитируемом тексте. Для суммы в таблице цитата должна содержать идентификаторы
той же строки. Предложения, которые не прошли проверку, остаются видимыми
для ручной сверки. В шаблон попадают сохранённые значения; ручные правки
и подтверждения сохраняются после повторного анализа.

DOCX использует нативный Flash с текстом, таблицами и формулами Word.
Ссылки на изображения из Markdown сохраняют позиции внутри текста.
Процессор дополняет экспорт только вложениями, которых ещё нет среди
изображений MinerU, сравнивая декодированные пиксели. OCR для вложенных
картинок на этом этапе не выполняется. На проверенной машине RTX 4060 ONNX
использует DirectML/CPU.
Устаревшие вложения WMF/EMF преобразуются в PNG в рабочей копии документа.
Если локальный декодер недоступен или вложение не читается, на его месте в
тексте появляется предупреждение. Предупреждения для вложений без определённой
позиции добавляются в конце результата. Загруженный исходник сохраняется без
изменений.
Standard/Advanced и удалённые VLM в этой конфигурации не включены.

## Контракт процессора

- `GET /v1/health`: режим `stateless-sdk`.
- `PUT /v1/attempts/:uuid?format=pdf|docx|jpg|png|webp|tiff|avif|heif`: raw bytes, до 20 MiB;
  ответ ZIP с Markdown и изображениями, заголовок `x-mineru-version`.
- `DELETE /v1/attempts/:uuid`: отменяет попытку, ждёт фактического завершения OCR,
  удаляет временный каталог и только затем возвращает 204. Поздний PUT того же ID
  получает 410. Повторный DELETE идемпотентен.

UUID назначает Anyko и сохраняет в ProcessorAttempt до отправки байтов. Поэтому
таймаут и неизвестный исход HTTP не теряют связь с обрабатываемым исходником.
TypeScript `createMineruParser` предоставляет `parseDocument(bytes,format,attemptId)`
и `eraseAttempt(attemptId)`. Произвольные result/upload URL от провайдера отсутствуют.
Redirect запрещён, ответы ограничены по размеру и deadline, ошибки статические.

Исходник и SDK TEMP/TMP/TMPDIR находятся в одном управляемом каталоге попытки.
Экспорт ZIP собирается в памяти; дополнительные JSON SDK не записываются на диск.
Одновременно выполняется один parse, модели остаются тёплыми. Отмена SDK дренирует
настоящий синхронный OCR thread: закрыть HTTP/asyncio-задачу недостаточно.
При запуске эксклюзивный process lock исключает параллельный сервис, после чего
оставшиеся job-каталоги очищаются до открытия HTTP. Junction/symlink roots отклоняются.
Сохраняются только пустые ID-only cancelled markers, без содержимого документов.

## Хранение и полное удаление

Адаптер извлекает `markdown.md` и проверенные JPEG/PNG/WebP из `images/`.
Ограничения: ZIP 10 MiB, Markdown 4 MiB, 256 картинок, 3 MiB каждая и 8 MiB суммарно;
проверяются объявленный и фактический размер, дубликаты путей, сигнатуры файлов.
Изображения сохраняются отдельными S3-объектами, JSON — только manifest. Правила
владения и подтверждаемого удаления: [вертикаль документов](document-vertical.md).
Для известных сбоев процессор передаёт ограниченный набор кодов в
`x-anyko-processor-error`. Worker записывает код результата распознавания,
а API состояния файла возвращает его вместе с сообщением. Страница
«Распознавание» показывает тост при обнаружении новой неудачной попытки.

При переходе со старого Tasks API сначала останавливается старый Anyko-процесс,
проверяется управляемый путь `work/mineru/uploads`, затем его кэш физически
удаляется. Durable-исходники в S3 при этом сохраняются. Старые Base64-результаты
переносятся командой `bun run artifacts:migrate --applications-stopped --storage-requests-drained`
при подтверждённо остановленных API/worker и завершённых storage requests.
Не допускается оставлять старый 24-часовой кэш как исключение из полного удаления.

## Проверка

```sh
bun run test:mineru
bun run test:processor
```

Тесты процессора используют FastAPI/httpx, вспомогательную функцию отмены из SDK
и экспорт DocVortex. Локально команда выбирает подготовленный Python venv.
CI устанавливает закреплённую версию MinerU без транзитивных зависимостей и
пакеты из `tests/processor/requirements.txt`. Загрузка весов моделей для этих
тестов не требуется. Live OCR проверяется отдельно:

```powershell
work/mineru/.venv/Scripts/python.exe infra/mineru/smoke.py --tier basic --format pdf
work/mineru/.venv/Scripts/python.exe infra/mineru/smoke.py --format docx
bun run smoke:document work/mineru/preview.docx
```

В smoke `--tier` управляет видом синтетической PDF-фикстуры (Basic — image-only,
Flash — text layer), а реальный режим процессора выбирается по формату. Никакие
клиентские документы в fixtures не включаются. Синтетический DOCX с таблицей,
картинкой и Word OMML-формулой проверяет связь SDK → S3 → браузер, но не качество
распознавания на реальном корпусе и не production deployment.

Для воспроизведения [#96](https://github.com/kindyakov/anyko/issues/96) используется
растровый `03-snils.pdf` (функция `card` в синтетическом генераторе v12).
Последовательность запроса совпадает с клиентом процессора:

```powershell
$attempt = [guid]::NewGuid()
$pdf = 'work/spec-61/follow-up/synthetic-router-v12/03-snils.pdf'
$url = "http://127.0.0.1:8020/v1/attempts/${attempt}?format=pdf"
curl.exe --fail --request PUT --header 'content-type: application/octet-stream' `
  --data-binary "@$pdf" --output "$env:TEMP/anyko-snils.zip" $url
curl.exe --fail --request DELETE ($url -replace '\?format=pdf$')
```

До исправления `markdown.md` содержал «Φ -» и «0-0-001 00». Basic с ONNX
обнаруживал все четыре области. OCR искажал две строки, ещё две оставлял
пустыми, после чего нормализация убирала пустые блоки. Это воспроизводилось
на CPU и DirectML. `auto`, `ocr` и `txt` дали одинаковый результат на карточке.
Поддерживаемый вызов `parse_async` не принимает язык OCR, DPI и порог разметки.
Штатный распознаватель Basic той сборки работал в режиме `ch`. Русский
проход Anyko с моделью `eslav` уверенно
прочитал все четыре строки, но на исходном растре смешал «о» и нули в номере.
Перебор масштаба от 61 до 200 DPI на этом растре не вернул полный номер.
Повтор на растре повышенной резкости при штатном масштабе дал строку
«Страховой номер индивидуального лицевого счёта 000-000-001 00». После
слияния она и «Форма АДИ-РЕГ» должны быть в `markdown.md`. Версии, веса
и настройки образа MinerU для того исправления не менялись.

После переключения распознавателя в [#97](https://github.com/kindyakov/anyko/issues/97)
та же карточка даёт полный СНИЛС в первичном OCR. Проверка геометрии
обнаруживает покрытие всех строк и пропускает повторное распознавание.
Три тёплых HTTP-запроса на образец на одном компьютере, ONNX CPU.
Время включает разбор, локальную проверку и сборку ZIP. На замеры влияли
параллельные локальные проверки.

| Синтетический вход                        | До, медиана мс | После, медиана мс |
| ----------------------------------------- | -------------: | ----------------: |
| Растровый PDF СНИЛС                       |           3987 |              2665 |
| Растровый PDF справки                     |           3088 |              3415 |
| PDF с нативным текстом                    |           1317 |              2310 |
| PNG паспорта                              |           2775 |              3150 |
| JPEG паспорта                             |           2487 |              2942 |
| DOCX справки                              |             68 |                62 |
| DOCX с вложенной растровой копией справки |             80 |               129 |

Узкое исправление похожих букв восстановило два номера договора и название
`VTB Bank`. На этом контрольном растре совпали 9 из 10 проверяемых значений
против 6 из 10 без исправления. В распознанном обозначении `AO «ТБанк»`
обе буквы `AO` остались латинскими. Контрольный нативный PDF и DOCX
сохранили исходное написание.

Первичный источник: [MinerU](https://github.com/opendatalab/MinerU), публичный Python
SDK и stateless `mineru-kit parse` версии 4.1.7. Кэшируемый `mineru parse` и старый
Tasks/FileStore server для этой схемы не используются.
