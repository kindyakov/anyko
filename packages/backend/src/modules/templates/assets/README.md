# Бланки пакета банкротства

Выбираемый пакет **bfl-bankruptcy-v14** использует бланки statement-v12.docx, inventory-v3.docx и creditors-v4.docx. В списке кредиторов шапки повторяются на продолжении таблиц. Дата и подпись держатся вместе с заключительным текстом во всех формах. Во всех трёх бланках используется одна дата заполнения комплекта. Просительная часть заявления повторяет сведения вводного абзаца и содержит утверждённый текст просьбы об отсрочке. Действующие договоры одного кредитора группируются в заявлении и списке, а итог учитывает каждый договор один раз. Опись распределяет имущество по подразделам формы, включая наличные средства и кадастровые номера. Версии пакета v12 и v13 доступны для ранее созданных работ. Исходные документы конкретного дела хранятся отдельно от поставляемых обезличенных бланков.

В [описании пакетов](../../../profiles/bfl/package-descriptions.ts) перечислены версии бланков, поля, приложения и план анализа. Миграции каталога фиксируют версии и контрольные суммы, включая `202611050012_bankruptcy_package_v4`. Изменение поставляемого бланка требует новой версии. Уже созданные работы остаются привязаны к своему бланку.

## Подготовка следующей версии

1. Сохранить исходный DOCX и его SHA-256 отдельно от поставляемого бланка. Инвентаризировать все текстовые части, таблицы, колонтитулы, примечания, поля и метаданные, не ограничиваясь `Document.paragraphs`.
2. Работать с копией OOXML-пакета. Сохранить неизменяемые части (styles, theme, numbering, fonts, отношения), геометрию секций и свойства заменяемых абзацев/ячеек. Заменять текст внутри выбранного абзаца с сохранением `w:pPr` и исходных свойств `w:rPr`. Не пересоздавать документ с нуля и не пересохранять его конвертером.
3. Текстовые слоты используют `{fieldKey}`. Для каждого тега версии создаётся запись `DocumentTemplatePlaceholder`. Формат `identity` сохраняет обычную подстановку по имени тега. Если одному полю нужны разные форматы, используйте отдельные теги с одним полем и разными строковыми `placeholder`, например `DD.MM.YYYY` и `D MMMM YYYY года`. Повторяемая строка таблицы начинается с `{#collection}` в первой ячейке и завершается `{/collection}` в последней. Колонки внутри используют `{name}`, `{basis}` и другие ключи из контракта поля. В метаданных вложенный тег указывается с ключом коллекции, например `debts.amount`. Одна строка обязательства соответствует одному договору. Свободные повествовательные блоки заменяются целиком, чтобы сохранить грамматическое согласование для новых данных.
4. Общие реквизиты задаются одними ключами во всех бланках. ФИО в реальном пакете собирается из `lastName`, `firstName`, `middleName`; самостоятельный `personName` остаётся только для архивного технического бланка. Адрес во всех документах использует общие компоненты. Имена, паспорт, идентификаторы, суммы, даты, работодатели, имущество и реквизиты приложений исходного дела должны исчезнуть из поставляемых частей; очистить метаданные автора.
5. Подготовить `blocks` предпросмотра из обезличенного `word/document.xml`: абзацы в исходном порядке, alignment, размер, bold, отступы; сетка таблиц, spans/merge и повторяемые строки. Веб не выполняет HTML/XML исходника. Теги трактуются как разрешённые слоты; остальные строки остаются статическим текстом React.
6. Проверить генерацию с длинными реквизитами и несколькими строками таблиц; проверить сохранность неизменённых OOXML-частей, отсутствие исходных значений и незаменённых тегов. Выполнить DOCX→PDF→PNG и осмотреть каждую страницу. Предпросмотр браузера не доказывает совпадение Word-пагинации.

## Публикация пакета

1. Поместите обезличенный DOCX в `assets/`. Укажите его версию, SHA-256 и блоки предпросмотра в [template-previews.json](../../../profiles/bfl/template-previews.json). Добавьте теги и требования к исходникам в [template-bindings.json](../../../profiles/bfl/template-bindings.json).
2. Добавьте описание версии пакета в [package-descriptions.ts](../../../profiles/bfl/package-descriptions.ts). Оно связывает версии бланков с набором полей, приложениями, указаниями и порядком анализа. Выберите зарегистрированную функцию заполнения и её параметры. Для бланков БФЛ функция `bfl-v1` принимает `layout` и необязательный `splitAttachments`.
3. Выполните `bun run test:works` и проверьте эталоны через `bun run test:bfl:reference` и `bun run test:bfl:acceptance` на выделенной тестовой БД и очереди. Предпросмотр и генерация используют общую функцию `prepareTemplate`.
4. После применения миграций выполните `bun run db:publish-packages` с `DATABASE_URL` нужной среды. Команда проверяет DOCX, сверяет строки каталога и сохраняет канонический JSON и его SHA-256 в одной транзакции. Повтор той же версии и содержимого возвращает `unchanged`. Расхождение прерывает публикацию. Новые версии выпускаются описанием, а уже применённые SQL-миграции сохраняются в истории.

Текущие копии сохраняют структуру и оформление исходных OOXML-пакетов. Удалены заполненные строки и персональные обстоятельства, вместо них введены поля и повторяемые строки. Общие правовые формулировки взяты из предоставленного образца; техническая готовность не удостоверяет их юридическую актуальность.
