# Бланки пакета банкротства

Выбираемый пакет `bfl-bankruptcy-v3`: `statement-v3.docx`, `inventory-v1.docx`, `creditors-v1.docx`. Пакет v1 сохранён исторически и не предлагается в UI. Просительная часть текущей версии полностью определяется полем `requestsDetails`, утверждения о приложениях — списком `attachments`; исходные утверждения конкретного дела не подставляются. Это обезличенные копии предоставленных документов. Исходные файлы конкретного дела не являются runtime-зависимостью и не предназначены для публикации.

`package.json` содержит версии, SHA-256 и структуру предпросмотра. Миграции `202611050009_document_packages` и `202611050010_bankruptcy_package_v2` и `202611050011_bankruptcy_package_v3` фиксирует эти же версии и суммы в каталоге. Изменение поставляемого бланка требует новой версии; старую версию для уже созданных работ не перезаписывают.

## Подготовка следующей версии

1. Сохранить исходный DOCX и его SHA-256 отдельно от поставляемого бланка. Инвентаризировать все текстовые части, таблицы, колонтитулы, примечания, поля и метаданные, не ограничиваясь `Document.paragraphs`.
2. Работать с копией OOXML-пакета. Сохранить неизменяемые части (styles, theme, numbering, fonts, отношения), геометрию секций и свойства заменяемых абзацев/ячеек. Заменять текст внутри выбранного абзаца с сохранением `w:pPr` и исходных свойств `w:rPr`. Не пересоздавать документ с нуля и не пересохранять его конвертером.
3. Текстовые слоты используют `{fieldKey}`. Повторяемая строка таблицы: `{#collection}` в первой ячейке и `{/collection}` в последней. Колонки внутри — `{name}`, `{basis}` и другие ключи из контракта поля. Одна строка обязательства соответствует одному договору, а не фиксированному номеру кредитора. Свободные повествовательные блоки заменяются целиком, чтобы не переносить чужие обстоятельства или грамматические формы.
4. Общие реквизиты задаются одними ключами во всех бланках. ФИО в реальном пакете собирается из `lastName`, `firstName`, `middleName`; самостоятельный `personName` остаётся только для архивного технического бланка. Адрес во всех документах использует общие компоненты. Имена, паспорт, идентификаторы, суммы, даты, работодатели, имущество и реквизиты приложений исходного дела должны исчезнуть из поставляемых частей; очистить метаданные автора.
5. Подготовить `blocks` предпросмотра из обезличенного `word/document.xml`: абзацы в исходном порядке, alignment, размер, bold, отступы; сетка таблиц, spans/merge и повторяемые строки. Веб не выполняет HTML/XML исходника. Теги трактуются как разрешённые слоты; остальные строки остаются статическим текстом React.
6. Проверить генерацию с длинными реквизитами и несколькими строками таблиц; проверить сохранность неизменённых OOXML-частей, отсутствие исходных значений и незаменённых тегов. Выполнить DOCX→PDF→PNG и осмотреть каждую страницу. Предпросмотр браузера не доказывает совпадение Word-пагинации.

Текущие копии сохраняют структуру и оформление исходных OOXML-пакетов. Удалены заполненные строки и персональные обстоятельства, вместо них введены поля и повторяемые строки. Общие правовые формулировки взяты из предоставленного образца; техническая готовность не удостоверяет их юридическую актуальность.
