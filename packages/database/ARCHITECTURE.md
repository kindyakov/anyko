# packages/database

Prisma schema, SQL-миграции, клиент, пул подключений и блокировки ресурсов. Транзакции для сценариев (`UnitOfWork`, непрозрачный `Tx`) собирает `backend/runtime`. Схема физически одна, но у каждой таблицы один предметный владелец в `backend/modules`. Импортировать пакет могут только persistence-адаптеры модулей (`infrastructure`), адаптер транзакции в `backend/runtime`, auth-адаптер и мигратор (`database-private`).

## Устройство

```text
prisma/schema.prisma     общая схема
prisma/migrations/<YYYYMMDD><номер>_<имя>/migration.sql   номер сквозной, четыре цифры
src/                     клиент, пул подключений, блокировки ресурсов
generated/               клиент Prisma, создаётся `bun run db:generate`, вне Git
```

Генерация клиента и исключение Knip для его зависимостей описаны в [README](README.md).

## Как добавлять

- **Таблица или колонка:** владелец, `workspaceId` и составные ключи для бизнес-данных, миграция и правила lifecycle ([данные и задания](../../docs/engineering/data-and-jobs.md#владение-и-изоляция)). Изменение схемы проверяет владелец данных.
- **Миграция:** каталог с текущей датой и номером, следующим за последним, затем `bun run db:generate`. Применённую миграцию не меняют: исправление — новая миграция. Миграция расширяет схему так, чтобы прежняя версия API и worker продолжала работать; удаление старого — отдельным выпуском ([порядок выпуска](../../docs/engineering/operations.md#порядок-выпуска)).
- **Версия пакета документов или бланка:** строки каталога вводит миграция; опубликованные версии не меняются ([README бланков](../backend/src/modules/templates/assets/README.md)).
