# apps/web

Кабинет юриста на Next.js. Маршрут компонует экран, feature владеет пользовательским поведением, общие визуальные элементы берутся из `@anyko/ui`. Данные читаются и меняются только через API; бизнес-операции в Server Actions и Route Handlers не дублируются.

## Устройство и правила

Структура, уровни `app` → `features` → `@anyko/ui`/`lib`, маршруты, данные, формы, тесты и рецепты добавления раздела, feature, запроса и команды — в [web.md](../../docs/engineering/web.md). Причины — [ADR 0008](../../docs/adr/0008-web-application-architecture.md). Главное:

- импорт чужой feature только через её `index.ts`;
- рабочая область в адресе `/w/[workspace]`;
- серверное состояние только через TanStack Query с фабрикой ключей;
- 401 и тексты ошибок — в `lib/api`.

## Интерфейс

- Внутренние импорты из `src` пишите через `@/`; соответствие задаёт `tsconfig.json`.
- Оформление компонентов — Tailwind CSS. `globals.css` содержит подключение Tailwind и семантические токены из [брендбука](../../docs/brand/brandbook.md). Используйте `bg-canvas`, `bg-surface`, `text-ink`, `text-muted`, `border-line`; основной акцент — `brand`.
- Интерфейс использует постоянную тёмную тему, заданную в корневом layout, независимо от настроек системы. Новые экраны проверяйте на настольной и узкой ширине. Шрифты бренда подключены локально.
- Все элементы с действием показывают `cursor-pointer`; отключённые — `cursor-not-allowed`. Общий Tailwind base layer в `globals.css` покрывает семантические элементы и интерактивные ARIA-роли.
- Интерактивные примитивы — Base UI; общие элементы находятся в `@anyko/ui`. Перед добавлением зависимости используйте существующий примитив. 21st.dev — источник образцов компонентов; при переносе кода проверяйте лицензию и фиксируйте происхождение.
- Для полей, форм, выбора, вкладок, переключателей, раскрывающихся секций и модальных окон используйте соответствующие Base UI primitives, а не нативные `select`, `details`, `dialog` или самописное поведение через ARIA. Семантическая разметка (`main`, `section`, заголовки, ссылки Next.js) остаётся HTML; многострочный ввод компонуется через `Field.Control render={<textarea />}`.
- Серверное состояние — TanStack Query; запросы проходят через `callApi` с endpoint-описаниями из `@anyko/contracts` (ответ проверяется их схемой), ключи и `queryOptions` лежат в `api/` своей feature; `requestApi` — внутренний транспорт `lib/api`. Zustand хранит клиентские настройки интерфейса, а локальная форма — собственный черновик. Серверные данные и секреты в persisted store не помещаются.
- Предпросмотр юридического документа сохраняет типографику исходного шаблона и белую бумагу. Динамические размеры из OOXML и измеренная высота textarea являются данными документа; для них допустимы inline styles, остальное оформление — Tailwind. Разбор и форматирование значений, общие с DOCX, берутся из `@anyko/document-values`, а не пишутся заново в feature.

Версия Next.js отличается от знакомой по обучению: перед кодом прочитайте нужное руководство в `node_modules/next/dist/docs/` (см. [AGENTS.md](AGENTS.md)).
